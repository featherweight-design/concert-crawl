## D. Open ambiguities

1. **`AccessPlaceholderChip` is unreachable from `GuideSection`.** The component is authored, styled, and exported, and `PLACEHOLDER_COPY.accessibility` is shipped copy — but `GuideSection` computes `authored = CHIP_ORDER.filter(k => copy[k])`, which drops accessibility entirely when its body is empty. Nothing in the prototype reads an `is_placeholder` flag on the display side. Eng must decide the display contract: a venue in placeholder mode presumably renders `AccessPlaceholderChip` in slot 1, but the handoff never wires it, and the thin fixture authors accessibility so the state is never exercised on canvas.

2. **What renders when a venue has neither authored nor placeholder accessibility** (i.e. an unpublished / partially-migrated venue). The admin publish gate prevents this going forward, but existing venues will start in that state. Options the handoff doesn't choose between: hide the whole guide section, render the placeholder chip anyway, or render the thin state with no accessibility chip.

3. **`StillGathering` renders all seven non-accessibility ghosts unconditionally**, ignoring which are authored. A venue with accessibility + parking authored would show Parking as both a real chip and a dashed ghost. Unspecified whether the ghost list should be `CHIP_ORDER` minus accessibility minus authored, or whether the thin state only ever applies when exactly one chip is authored.

4. **The thin/populated threshold is undefined.** `mode` is a canvas prop. Nothing states how many authored chips (or which) flip a venue from `thin` to `populated`, nor whether a venue with a vibe line but few chips counts as populated.

5. **Venue-name interpolation form is unspecified.** `CALLOUT_COPY.*.q`, `EVENT_CHIP_COPY`, and `PLACEHOLDER_COPY.thinFooter` all embed `Roxy` — a _short_ name, distinct from `ROXY_VENUE.name` (`"The Roxy"`) and from `ROXY_EVENT.venueShort` (`"Roxy"`). There is no `shortName` on the venues schema per READINESS's own schema sweep. Eng must decide: add a short-name column, derive it (strip leading article), or use the full name and accept `"First time at The Roxy?"`. `PLACEHOLDER_COPY.thinFooter` additionally uses a possessive (`Roxy's`), which breaks for names ending in `s`.

6. **`CHIP_DEFS[*].adminHint` is authored for all 8 chips but never rendered anywhere in `guide-admin.jsx`.** Only `ADMIN_COPY.fieldPlaceholder` reaches the UI. Unspecified whether the hints are dead copy, intended as tooltip/help text under each chip field, or intended for the picker.

7. **`⌘↵ publish` is advertised but not implemented.** No keydown handler exists. Whether the shortcut is in scope for v1 is unstated.

8. **`Save draft` has no behaviour and no persisted draft state.** READINESS explicitly says publish state is "not a persisted state; derived UI only" — which leaves what `Save draft` writes, and whether an unpublished guide is hidden from the consumer page, unspecified.

9. **No `aria-live` / `role="alert"` on the validation banner**, and no `aria-invalid` / `aria-describedby` linking the accessibility textarea to its error message. The banner appears on `Publish guide` click, so a screen-reader user gets no announcement. The handoff's a11y section claims "the required-field error is text + icon + color" but doesn't address announcement.

10. **No `<label>` associations on any admin textarea.** `AFieldLabel` renders a `<span>`, not a `<label htmlFor>`, and the textareas carry no `aria-label`. Every admin field is effectively unlabelled to assistive tech.

11. **Chip state dots convey state by colour + fill alone**, with no text alternative or `aria-label`, on both the field labels and the legend. The legend supplies the mapping, but the dots themselves are unlabelled.

12. **Returner accordion has no `aria-controls`** and the panel has no `id`; content unmounts rather than using `hidden`. Also unspecified: whether the open/closed state persists across navigations, and whether an incoming `#ft-guide` deep link (from the event chip) should force-open a returner's collapsed accordion — the event chip anchors to `#ft-guide` but a returner arriving there would land on a collapsed card.

13. **Desktop 2-column chip grid sets `first={true}` on every chip**, removing all top borders — so the desktop grid has no row separators at all. Unspecified whether that's intentional or a side effect of reusing the `first` flag for border suppression.

14. **Admin mobile is undrawn** (README gap item 3, READINESS recommends "OK for v1"). Not resolved, just deferred — the block's behaviour below ~600px is unspecified.

15. **`GuideChip` renders `value` as a single text node** with no line-break or markdown handling, while `AdminTextarea` uses `whiteSpace: "pre-wrap"` and accepts multi-line input. An admin who types paragraphs gets them collapsed on display. Unspecified whether newlines should be preserved on the consumer surface.

16. **No max-length on any field.** The returner preview strip and the chip bodies have no truncation rule beyond the preview strip's single-line ellipsis.

17. **The Directions link, About eyebrow, "Before you go", "New here", "GUIDE", "★ ALWAYS HERE", "NOT DOCUMENTED", "First-timer guide", "The stuff worth knowing before you walk in", the event chip's `→`, and every admin literal flagged "needs a key" above are hard-coded inline strings**, not in a `*_COPY` map — despite `feedback_definitions_copy_rule` requiring all customer-facing strings in `definitions/copy.ts`. Eng must invent the keys; the handoff doesn't supply them.
