# #1115 — Dedicated Artist UI — Engineering Implementation Plan

**For agentic workers:** this plan is written to be executed top-to-bottom by an agent with no
prior context on #1115. Every task names the exact files it touches and the exact test that
proves it. Do not reorder PRs — the sequencing lock in this document is load-bearing (PR-B
creates the table PR-C/D/E read from). If a step's premise turns out to be wrong when you open
the file, stop and report rather than improvising a different design.

**Goal.** Ship a public artist detail route at `/artists/{slug}` that answers "who is this and
when are they playing", converts the majority no-upcoming-shows case into a Follow, and gives
`#643`'s supporting-artist names somewhere to point.

**Architecture.** Next.js App Router page (server component shell + client islands) → Hono
`/v1/artists/*` → Drizzle → Postgres. A new expand-only `artists` projection table supplies the
URL slug and the cached Spotify identity; `events.canonicalArtist` / `events.canonicalSupporting`
remain the join surface.

**Tech stack.** Next App Router (15.x at time of writing — take the version from `apps/web/package.json`, not from this line), Hono, Drizzle, Postgres, Clerk, Zod, Vitest, Playwright.

**Spec.** `docs/superpowers/specs/2026-07-24-1115-artist-page-design-brief.md`

**Design handoff.** `design/design_handoff_artist_page/` — `CLAUDE_CODE_HANDOFF.md` is the
authoritative measurement doc; `READINESS.md` is 🟢 Green with five open items, all resolved
below (see **Resolved open items**).

**Predecessors.** `#643` supporting artists (data + UI, merged) supplies
`events.supportingArtists` / `events.canonicalSupporting`. `#763` Spotify sync supplies
`user_artist_follows` and `apps/api/src/lib/spotify.ts`.

**Adjacent.** `#794` logged-out UX (`docs/superpowers/specs/2026-07-25-794-logged-out-ux-design-brief.md`)
declares `/artists/[slug]` public. This plan ships the route inside `(protected)` with a
token-optional data path so #794's flip is a directory move plus one matcher entry.

## Global Constraints

- **TDD.** Every step writes the failing test first, runs it, sees it fail for the stated reason,
  then implements. `Run:` and `Expected: FAIL` lines are not decoration.
- **Worktree.** All work happens in a worktree under `.worktrees/`. The main repo directory stays
  clean. `git -C "$(git rev-parse --path-format=absolute --git-common-dir)/.." status` before every
  push.
- **Locked vocabulary.** **Watching** (never Saved/Favorites); **Submitted prices**; **price check**.
  "Following" is a *separate, legitimate* concept for artists via `user_artist_follows` — an artist
  is **followed**, a show is **watched**. The Watching affordance is a lucide `Eye`. There is no
  heart icon in this product: no heart glyph may be rendered, and the string `heart` must not appear
  in any customer-facing copy, component name, icon import, or CSS class this plan ships. (Prose
  that states the rule — this plan, and the tests that assert it — is obviously exempt.)
- **Copy rule.** Every customer-facing string lives in a `definitions/copy.ts`. `ARTIST_COPY` is
  lifted verbatim from `design/design_handoff_artist_page/artist-data.jsx` into
  `apps/web/src/components/consumer/artist-page/definitions/copy.ts`. `CRAWL_SINCE` is **data**,
  not copy — it goes in `definitions/constants.ts`.
- **No `as` casts.** Zod `safeParse` at every boundary, type guards for narrowing, declaration
  merging for library types. `apps/web/src/lib/api.ts` already models the guard style.
- **Zod at every Hono endpoint.** All routes under `/v1/`.
- **Drizzle only.** Expand/contract migrations. Next migration number is **0064** (last shipped is
  `packages/db/migrations/0063_vendor_picker_values.sql`). Verify before writing — concurrent
  branches may have claimed it.
- **Mobile/desktop parity is non-negotiable and lands in the same PR.** Every UI task is verified
  at 390px, 320px, and desktop. `AP_NARROW_BP = 360`; 320 is the floor.
- **Tokens only.** `var(--token)`, `color-mix(in oklab, …)`. No hardcoded hex, no Tailwind `dark:`
  variants, works across all nine themes. The single sanctioned exception is
  `EMBED_LIGHT_PLATE = "#191A1F"` (Task 19) — Spotify's iframe is always dark, so the plate behind
  it must be dark even in light themes.
- **a11y in the same PR.** 44px minimum targets, real `<h1>`/`<h2>`, correct `aria-*`, full
  keyboard path. No native `title=` **tooltips** on interactive UI — this bans `title` used to
  convey hover-only information, not the `title` attribute where ARIA requires it for labelling
  (a `<iframe title=...>` is required and expected, matching `MapPlaceholder.tsx`).
- **Release notes.** `apps/web/src/lib/definitions/releases.ts` gets one entry, on the branch that
  ships the user-visible route (PR-F).
- **`progress.md`.** One ✅ row on PR-F. Not on PR-A/B/C.
- **Pre-push, in the worktree:** `pnpm typecheck && pnpm lint && pnpm test`. Integration tests need

## Phase / PR-B — The `artists` projection table

The route needs a URL-safe, stable identity. `canonicalizeArtist()` in
`packages/crawler-core/src/lib/canonical-artist.ts` lowercases and strips diacritics but
**preserves punctuation** — `AC/DC` → `ac/dc`, `P!nk` → `p!nk`, `M.I.A.` → `m.i.a.`. None of those
are URL-safe. Slugging must therefore be a distinct, stored derivation, and collisions between
distinct canonical names (`m.i.a.` and `mia`) must be resolved at write time.

**Do not** implement slugify as a Postgres generated column. SQL↔JS canonicalization parity has
already produced a production bug in this repo (the Ø/ø incident). One JS implementation, one
migration that calls it via a backfill script.

### Task 8: Confidence-gated matcher

**Files:**
- Create: `apps/api/src/lib/artist-match.ts`
- Create: `apps/api/src/lib/artist-match.test.ts`

**Interfaces:**

```ts
interface ArtistMatchResult {
  status: 'matched' | 'ambiguous' | 'no_match'
  spotifyArtistId: string | null
  confidence: number | null
  photoUrl: string | null
}
export const matchArtist = (canonicalName: string, deps: { search: SpotifySearch }) => Promise<ArtistMatchResult>
```

Design brief §3.2 locks *that* matching is confidence-gated and leaves the scoring to engineering.
Scoring, in order of authority:
1. `canonicalizeArtist(candidate.name) === canonicalName` → exact. Confidence `1.0`.
2. Exact canonical match on **more than one** candidate → `ambiguous`, regardless of popularity.
3. No exact canonical match → `no_match`. Do **not** fuzzy-match. A wrong artist photo is worse
   than no photo, and the brief's §3.3 fallback is a designed state.

The bar is `confidence >= 1.0` today. It is expressed as a named constant
(`ARTIST_MATCH_MIN_CONFIDENCE`) so a future fuzzy tier can lower it without a rewrite.
