## Inherited decisions (locked by handoff)

These are settled — the implementation PR must respect them:

- Single full-bleed surface, no `AppBar` / `FilterBar` / bottom nav.
- Three flavors (`show` / `generic` / `display`) defined; **`display` reserved** — do not ship without product sign-off.
- Single CTA: `Browse tonight's shows →` linking to `/`. No router-back, no secondary CTA, no "Report this".
- Poster is theme-independent. `IdentityArt` palette is hashed from `posterName`, not retinted by the active theme.
- Default `posterName="404"` — deterministic, ship the single seed.
- CTA is a real `<a href="/">` — works without JS, supports middle/cmd-click.
- One `<h1>` per page (the headline). Status rail is decorative.
- Use existing `IdentityArt` (`apps/web/src/components/consumer/identity-art/IdentityArt.tsx`) and `CCMark` (`apps/web/src/components/brand/cc-mark/CCMark.tsx`) — do not ship the local prototype copies.
- All tokens used must come from the existing token set in `apps/web/src/theme/themes.ts`. No new tokens.
- Inter (UI) + JetBrains Mono (metadata). No other typefaces.
- Mobile + desktop parity per `feedback_mobile_desktop_parity.md` — both ship, layout-token-driven, single shared `<NFContent>` per the handoff anatomy.

## Eng-side decisions (resolving READINESS.md clarifications)

Each item below corresponds 1:1 to an item under "Eng-side clarifications" in the readiness review.

### 1. `attemptedPath` source — option (a): middleware injection

**Decision:** Add an `x-pathname` request header in `apps/web/src/middleware.ts` and read it from `headers()` inside `not-found.tsx`. Fall back to `"/"` if absent.

**Rationale:** The mono footer is brand-significant ("we saw your URL" feels honest). Middleware addition is a one-line `NextResponse.next({ request: { headers: ... } })` pass-through; the cost is negligible and the header is stable across Next.js versions, unlike the internal `x-invoke-path`. Fallback to `"/"` keeps the footer harmless if the header is ever missing (edge cases, static export, future framework changes).

**Implementation sketch (middleware):**

```ts
// Inside the clerkMiddleware handler, before the auth resolution:
const requestHeaders = new Headers(req.headers)
requestHeaders.set('x-pathname', req.nextUrl.pathname)

// Every non-redirect branch must explicitly return this response — not
// `return` (undefined) — so the modified header reaches the downstream handler.
const passThrough = NextResponse.next({ request: { headers: requestHeaders } })
```

**Important:** Next.js middleware that returns `undefined` (or no value) does NOT carry modified request headers. The plan requires restructuring every non-redirect branch in `apps/web/src/middleware.ts` to explicitly return `passThrough` (or an equivalent `NextResponse.next({ request: { headers: requestHeaders } })`) instead of bare `return`.

This includes the path **after** `await auth.protect(...)` — `auth.protect` is not actually terminal for the success case. On unauthenticated requests it produces a redirect (terminal), but on authenticated requests it resolves and control falls through; today the handler then returns `undefined`, which would drop the injected header for exactly the authenticated routes where the 404 page renders most often. The impl PR must explicitly `return passThrough` after the `auth.protect` call.

The redirect short-circuits (`NextResponse.redirect(...)`) are genuinely terminal — they produce a complete response and skip the header injection by design. Every other site needs `return passThrough`. Touch every `return` (no value), `return;`, and post-`auth.protect` flow-through in the success path; the test sweep below covers the regression risk.

Pathname-only is intentional — `req.nextUrl.pathname` excludes `?query` and `#hash` strings, which keeps any accidental query-string PII (`?token=...`, `?email=...`) out of the breadcrumb and footer. If we ever need the search string, it requires a separate, audited decision and a different header.

### 2. Copy externalization — `definitions/copy.ts`

**Decision:** Create `apps/web/src/app/_components/not-found/definitions/copy.ts` and move all string literals there. Pattern matches existing `apps/web/src/app/_components/definitions/copy.ts` (landing copy).

**Strings to move:**

- Flavor copy table (`show` / `generic` / `display`): eyebrow, pill label, headline, body, stamp.
- Status rail: `ROUTE NOT FOUND`, `404` (code).
- Mono footer: `You tried`.
- CTA label: `Browse tonight's shows →`.
- Aria/decorative strings (any).

Component receives copy via direct import; no prop drilling. Per `feedback_definitions_copy_rule.md`, proper nouns / paths are data not copy — `attemptedPath` stays as a prop.

### 3. Wordmark reuse — `CCMark` + `AppHeader` wordmark

**Decision:** Use the canonical `CCMark` component and the wordmark sizing from `apps/web/src/components/consumer/app-header/AppHeader.tsx`. Do not re-implement `NFWordmark` inline.

**Implementation (in the follow-up implementation PR, not this docs-only plan PR):** Lift the `concertcrawl.` wordmark element from `AppHeader` into a shared `apps/web/src/components/brand/cc-mark/CCWordmark.tsx` if it isn't already extractable, and consume both from the 404 surface. `AppHeader.tsx` currently keeps the wordmark element inline at both the mobile bar (line ~43) and the desktop TopNav (line ~68); the implementation PR extracts it so the 404 surface and the header share one source. Keep the `.` accent in `var(--accent)` and the Inter 800 sizing — **but the sizing choice between breakpoints requires Hugh's explicit call before the impl PR opens**. The 404 handoff's `README.md:142` documents `17 (mobile) / 19 (desktop) · -0.02em` with the language "Do not restyle." The shipped `AppHeader.tsx` currently uses `text-[17px]` at both the mobile bar (line ~43) and the desktop TopNav (line ~68) — a drift from the handoff intent. Two paths forward:

- **Path A:** Implementation PR lifts `AppHeader` (and the extracted `CCWordmark.tsx`) to 19px on desktop to match handoff intent. Honors "Do not restyle" at the cost of touching shipped surfaces.
- **Path B:** Plan locks 17px on both breakpoints, accepting drift from the handoff, AND opens a `type: design` follow-up to confirm the wordmark sizing intent. Honors shipped parity at the cost of contradicting the handoff's "Do not restyle."

This plan does NOT pre-commit to either path; the impl PR opens with Hugh's selected path locked. If unblocked, **default to Path A** (honor the handoff's explicit `Do not restyle` instruction).

### 4. `attemptedPath` length cap — 120 chars with mid-truncation

**Decision:** Cap the rendered `attemptedPath` at exactly 120 visible characters. If the source path is longer, render `<prefix>` + `…` + `<suffix>` where prefix is the first 80 chars and suffix is the last 39 chars — total 80 + 1 (ellipsis) + 39 = 120. Example: `/very/long/url/segment/.../trailing-slug-here-segment`.

**Rationale:** A pasted 2KB URL would otherwise stretch the mono footer's height arbitrarily. 120 is two lines of the mono font at the documented size on the narrow mobile breakpoint, which is the right "you saw your URL, we saw it too" affordance without ruining the layout. Mid-truncation preserves both the route shape (prefix) and the trailing slug or segment (suffix) that's usually the part the user is most likely trying to verify; plain right-truncation hides that tail. Note: `attemptedPath` is pathname-only per item 1 — no `?query` or `#hash` — so the suffix is always a path segment, never a query parameter.

A unit test will exercise the truncation helper directly (no DOM needed).

### 5. Telemetry — Sentry breadcrumb in v1

**Decision:** Ship a Sentry breadcrumb on render with `{ category: 'navigation', message: 'not-found', data: { flavor, route: 'global' | 'event' | 'venue' } }`. **Do NOT include the raw `attemptedPath` in the breadcrumb payload.** Use `@sentry/nextjs` server-side (`Sentry.addBreadcrumb`) — `not-found.tsx` is server-rendered.

**Rationale:** Sentry is already wired (`apps/web/sentry.{client,server,edge}.config.ts`). A breadcrumb is zero-cost when no error is captured and tags any captured exception with which 404 surface the user was on. The user's identity is already linked to the Sentry event via Clerk (since `not-found.tsx` runs after middleware in the authenticated request lifecycle), so we don't need the path in the breadcrumb to investigate a specific user's 404.

**Why no raw path:** Even with pathname-only sourcing (item 1 strips `?query` and `#hash`), pathnames are user-controlled and can carry PII — `/users/hugh@featherweight.design`, `/orders/CUSTOMER-12345`, etc. The flavor + route shape (`'global' | 'event' | 'venue'`) gives enough signal to answer "which 404 surface is hit most often" without ever sending the raw path to Sentry. If we later want stats on the most-common 404 *route shapes*, we can derive them from a structured allowlist (e.g., `/events/[id]` vs. `/events/abc-123`) at that time; the v1 breadcrumb stays minimal.

The on-page mono footer still shows the user their own `attemptedPath` (item 1 + item 4 truncation) — that's first-party UX, not telemetry, and only the user sees it. Two different surfaces with different audiences.

### 6. Soft-404 — only the suggestions content is deferred; route-scoped files ship in v1

**Decision:** Only the **richer suggestions content** (did-you-mean / "we couldn't find that show, here are similar artists" + the supporting data work) is deferred to a follow-up ticket. The route-scoped `not-found.tsx` files at `events/[id]` and `venues/[slug]` **DO ship in v1** under item 9 below with `flavor="show"` and the standard handoff-defined headline. Unknown event/venue IDs in v1 land on those route-scoped files (not the global generic), so the brand-locked "show" anatomy is live on the surfaces where it matters most starting day one.

**This diverges from READINESS.md item 6**, which recommended deferring the route-scoped `not-found.tsx` files themselves to the same follow-up. The plan PR makes a different call:

- The handoff README's inherited decision is explicit — `flavor="show"` at event-shaped routes, `flavor="generic"` at the global catch-all. Shipping the route files in v1 honors that inherited decision. Deferring them would push the global `generic` flavor onto event/venue unknown-ID routes, which the inherited decision rules out.
- The route files are cheap — a few lines each, all referencing the shared `NotFoundScreen` component. The cost of including them in v1 is negligible compared to the brand value of the show-flavor poster on event-shaped unknowns.
- The richer suggestions content is a distinct, much larger design problem (suggestion ranking, click-through behaviour, empty-state when there are no suggestions). That work doesn't need to block the brand anatomy from going live.

**Follow-up:** Open a `type: design` ticket for "Soft-404 with did-you-mean suggestions for unknown event/venue IDs" after this PR merges. Reference this plan and Open Question #2 of the handoff README. The follow-up modifies the route-scoped `not-found.tsx` files (which exist after this PR) to add the suggestion content — it does NOT create those files.

### 7. Poster rotation — locked to `posterName="404"`

**Decision:** Hardcode `posterName="404"` everywhere in v1. Do not expose a rotation list or random-pick logic.

**Rationale:** Consistency is the brand asset here. The same poster on every 404 is a small recurring visual identity; the rotated list is easy to add later if product disagrees after launch.

### 8. Smoke test — Playwright spec in `apps/e2e/src/smoke/`

**Decision:** Add `apps/e2e/src/smoke/not-found.spec.ts` covering:

- Fetching `/this-definitely-does-not-exist` returns HTTP 404 on direct request.
- The rendered page has exactly one `<h1>` whose text matches the `generic` flavor headline copy.
- The `<a href="/">` "Browse tonight's shows" link is present and clickable.
- The wordmark renders.
- The mono footer renders the attempted path (sanity check; full middleware exercise).

Also add a unit test (`apps/web/src/app/_components/not-found/lib/truncate-attempted-path.test.ts`) for the 120-char mid-truncation helper covering: short paths pass through, exact 120 passes through, >120 truncates with `…` and preserves prefix + suffix lengths, empty string returns `"/"`.

The smoke test runs in the existing `apps/e2e` package using the `playwright.smoke.config.ts` setup that's already wired into prod hourly smoke runs.

### 9. Flavor selection at route mount — ship all three route files in v1

**Decision:** The implementation PR (separate, follow-up) ships three `not-found.tsx` files:

- `apps/web/src/app/not-found.tsx` — global catch-all, `flavor="generic"`.
- `apps/web/src/app/(protected)/(main)/events/[id]/not-found.tsx` — route-scoped, `flavor="show"`.
- `apps/web/src/app/(protected)/(main)/venues/[slug]/not-found.tsx` — route-scoped, `flavor="show"`.

**Rationale:** Inherited decision #7 in the handoff README is explicit: "Default ship is `posterName="404"`, `flavor="show"` at event-shaped routes, `flavor="generic"` at the global catch-all." Shipping all three respects the inherited decision and gets the brand-locked `show` flavor live on the surfaces where it matters most (the only two dynamic consumer routes). The soft-404 follow-up (item 6) is about *content richness* on those route-scoped 404s (suggestions, did-you-mean), not about the route files themselves — so this v1 lays the route surface today and the follow-up swaps in richer content later.

**`display` flavor is NOT shipped** — reserved per inherited decision.

## Implementation order

1. **Middleware** — add `x-pathname` header pass-through. Confirm no regression by running the existing auth/onboarding tests locally.
2. **Copy file** — write `definitions/copy.ts` against the handoff's flavor table.
3. **Truncation helper + unit test** — write `truncate-attempted-path.ts` and tests; TDD-friendly, no DOM.
4. **Wordmark extraction** — if `AppHeader` carries the wordmark inline today, extract to `CCWordmark.tsx`. Replace the `AppHeader` call site to confirm parity.
5. **`NFPoster`** — wrap `IdentityArt`, add the four overlays (eyebrow, pill, stamp, faux date). Use the `ia_isDark` helper for stamp contrast.
6. **`NFContent`** — status rail, headline, body, CTA, mono footer. Wire copy from `definitions/copy.ts`. Apply truncation helper.
7. **`NotFoundScreen`** — compose `NFPoster` + `NFContent`. Add `@media (min-width: 768px)` rule for layout switch (or split into Mobile/Desktop components — see file layout note).
8. **Route files** — three `not-found.tsx` files. Each reads `headers().get('x-pathname')`, fires Sentry breadcrumb, renders `<NotFoundScreen flavor={...} attemptedPath={...} />`. **No `themeKey` prop is passed.** Themes are applied entirely client-side today — `apps/web/src/app/layout.tsx` runs a blocking `themeScript` that reads `localStorage` `cc-theme` and sets `data-theme` on the `<html>` element before paint, with CSS variables coming from the existing `THEMES` map. The 404 surface consumes the same `var(--*)` tokens via that mechanism; no server-side theme source exists today and this PR does not add one. The handoff's `themeKey` prop is a design artifact from the standalone prototype; the production component drops it.
9. **Smoke test** — `apps/e2e/src/smoke/not-found.spec.ts`. Run against local dev to confirm.
10. **Changelog** — add release entry (see Release notes plan).
11. **Manual QA** — exercise all three routes locally across Electric / Jade / Light themes on mobile + desktop viewports. Verify `<h1>` count, CTA href, status rail decorative, IdentityArt renders, wordmark renders, mono footer renders truncated path correctly.

## Test plan

- `truncate-attempted-path.test.ts` — short path passes through, exactly-120-char passes through, >120 truncates with mid-ellipsis and preserves prefix (80) + suffix (39) lengths totalling exactly 120 visible characters (80 + 1 ellipsis + 39), empty/undefined returns `"/"`.

**Smoke (Playwright, prod-hourly)**

- `apps/e2e/src/smoke/not-found.spec.ts` — runs under the existing `playwright.smoke.config.ts`, which loads `storageState: '.auth/smoke.json'` so every test runs as the smoke user. This matters here: `apps/web/src/middleware.ts` redirects unauthenticated traffic on unknown paths to `/`, so an unauthenticated probe would never reach the 404 surface. All assertions below use the signed-in smoke context.
  - Hit `/this-definitely-does-not-exist` via `page.goto(...)` (signed-in storageState). Assert the response is HTTP 404 — capture via `page.on('response', ...)` for the document request, or use `request.get(...)` against the same authenticated context.
  - Exactly one `h1` matching generic flavor headline.
  - `a[href="/"]` containing CTA copy is present.
  - Wordmark renders.
  - Mono footer renders the attempted path.
